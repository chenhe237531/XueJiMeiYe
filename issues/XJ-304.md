## 背景

- `game.controller.ts` 已有转盘等抽奖模型，盲盒可复用其概率与发奖逻辑，避免重复实现。
- `FamilyLink` 模型已存在，接力棒在其之上扩展即可（按 D3 仅限已绑定家人）。

## 范围与实现要点

1. 接力棒：`GET /app/family/relay`（接力状态、双方记录、本周格子）、`POST /app/family/relay/pass`（接棒，双方各 +5 积分并写 `PointsLedger`）。
2. 盲盒：`GET /app/games/box`（剩余次数、奖品池）、`POST /app/games/box/open`（服务端随机发奖，返回奖品）。
3. 集章册：`GET /app/stores/stamps`（门店列表、盖章状态）、`POST /app/stores/stamps/:id`（顾问扫码盖章，一月一店限一枚）。
4. 所有积分变动必须写 `PointsLedger` 并更新余额，保持与现有积分体系一致。
5. 按 D4，知识卡内容源需明确；若为 AI 生成必须标注「不构成医学建议」。
6. 盲盒概率公示字段随接口返回，供页面展示。

## 验收标准

- [x] 六个接口均有响应示例，字段与设计文档一致。
- [x] 接棒一次双方各 +5 积分，余额与流水一致；同一天重复接棒被拒。
- [x] 盲盒随机性在服务端，前端无法预知结果；剩余次数正确扣减。
- [x] 重复盖章被拒（一店一月一枚）。
- [x] 并发请求下积分与次数不出现超发。
