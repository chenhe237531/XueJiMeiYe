## 背景

- 设计文档要求徽章墙与我的页展示成长进度，但 `/app/me` 目前不含成长与徽章字段。
- 设计按 24 枚徽章（坚持 8 / 探索 8 / 分享 8）规划，需确认运营是否够用（D2）。

## 范围与实现要点

1. 新增 `GET /app/achievements`：返回 `{ unlocked, total, groups[] }`，每组含徽章列表、点亮状态、进度（如 `19/30`）。
2. 徽章解锁条件由现有数据推导：积分流水、档案完整度、家人绑定数、签到记录；推导结果幂等写入 `UserBadge`。
3. 扩展 `GET /app/me`：新增 `nextTier`、`growthValue`、`badges`（已解锁徽章摘要）。
4. 提供徽章定义的集中配置（code / 名称 / 分组 / 条件 / 图形名），供前端 `XBadge` 消费。

## 验收标准

- [x] 徽章接口返回结构清晰，前端可直接渲染 3 组 × 3 列网格。
- [x] 重复调用不产生重复徽章记录（幂等）。
- [x] `/app/me` 新增字段不破坏既有前端（旧字段全部保留）。
- [x] 徽章名称与解锁条件可在同一处配置中查到。

**实现**（只动 files_own：`tier.service.ts` + `app.controller.ts`，+170 −1）：

1. **BADGES 24 枚目录**（D2 定稿，集中配置于 tier.service.ts 一处）：坚持 8 / 探索 8 / 分享 8，每枚含 `code / name / group / icon（彩色图形名）/ outline（线稿图标名）/ desc（解锁条件文案）/ target / stat`。XJ-301 seed 的 5 个演示 code 原样收编，演示数据无缝过渡。
2. **badgeStats()**：一次 `Promise.all` 取齐数据源——签到记录（连签/累计/喝水/运动/方案）、小镜消息（按天去重）、积分流水（quiz/visit/game_tree/match3/redeem 计数 + 正向汇总）、完成测评数、档案完整度（称呼/出生年份/性别）、家人绑定、接力记录（按天去重 + 连续天数）、门店印章（枚数 + 去重门店数）。连签口径与 `/app/checkins` 的 streak 一致（今天未签从昨天起算）。
3. **syncBadges() 幂等落库**：progress 永远写当前值，`unlockedAt` 只在首次达标时写入，已有行仅在值变化时 update——重复调用零副作用。
4. **GET /app/achievements**：`{ unlocked, total, groups[] }`，每组 `{ key, name, badges[] }`，前端可直接渲染 3 组 × 3 列网格。
5. **GET /app/me 扩字段**：`nextTier`（下一级档位/阈值/差距，A 档与无规则时 null）、`growthValue`（近 N 月实付，等级规则同源）、`badges`（unlocked/total + 最近 3 枚摘要）。
6. **给 XJ-403 的消费提示**：`outline` 为 Tabler 线稿图标名，需登记 uno.config.ts safelist；`icon` 为 xj/graphics.ts 的 GraphicName（badge-*/play-*/care-*/mood-*/store-*/talk-*/doc-* 均已存在）。
