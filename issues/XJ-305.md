## 背景

- `home.service.ts` 已按 `data.components` 生成首页配置，具备编排能力，但还没有「今日任务」模块。
- 按 D1 决议执行：依当期六维短板 + 待办（体检券 / 测评 / 方案）动态生成，不使用固定文案。

## 范围与实现要点

1. 在 `home.service.ts` 中新增「今日 3 件事」生成逻辑：优先取六维短板，其次取待办（未用体检券 / 未完成测评 / 方案里的日常小事）。
2. 最多返回 3 项，已完成项从今日清单剔除。
3. 每项返回：`code`、标题、副标、目标值 / 当前值、跳转路径、图标语义枚举。
4. 访客返回空数组（首页不展示任务卡）。
5. 结果随 `GET /app/home` 一起下发，不新增接口。

## 验收标准

- [x] C / B / A 会员返回 3 项任务，访客返回 0 项。
- [x] 已完成的任务不在清单中；完成任务后刷新首页确实少一项。
- [x] 每项都带可用的跳转路径，点击可达。
- [x] 生成逻辑对「无档案 / 无方案」的新用户有兜底任务（按 D1：降级为「完成首次六维测评」）。

## 交付记录（hourly-agent · 2026-10-17）

**实现**（只动 files_own 内 `home.service.ts`，+82 −1）：

1. `DIM_ACTIONS`：六维短板 → 日常动作映射（skin→喝水 / shape、fitness、posture→运动 / mind→小镜对话；轮廓维度无自然日常动作不映射）。`action` 同时是「今日完成」判定键：water / exercise = 当日有对应类型打卡，mirror = 当天与小镜有对话。
2. `todayTasks()` 三层生成：① 六维短板（< 60 分，弱→强排序，同动作去重，当日已完成剔除进 `doneToday`）→ ② 待办（体检券 / 首次或续答测评 / 方案日常小事进度）→ ③ 补位（当日无打卡 / 未与小镜聊过）。取前 3 项。
3. `taskList` 组件显式支持 + 登录用户布局未配置时自动注入（插在 healthCard / elderToday 之后）；访客不下发。
4. 每项含 `code / icon（D15 语义枚举）/ title / sub / target / current / link / points`。

**验收自检表**：

| # | 验收标准 | 结果 | 证据 |
|---|---|---|---|
| 1 | C/B/A 返回 3 项，访客 0 项 | ✓ | 陈总（A）3 项：dim_skin（喝水）+ dim_mind（小镜）+ checkup_coupon；王阿姨（C 乐龄）3 项：dim_posture + plan_daily + checkin_today；访客 components 无 taskList |
| 2 | 已完成任务不在清单、刷新少一项 | ✓ | POST /app/checkins {type:"exercise"}（+2 分）后刷新：doneToday=["dim_posture"]，清单 3→1（checkin_today 亦因当日已有打卡而消失） |
| 3 | 每项跳转可用 | ✓ | 全部带 link（/pkg-points/checkin、/pkg-plan/detail、/pkg-checkup/coupons、/pages/mirror/index、/pkg-assess/intro） |
| 4 | 无档案新用户兜底 | ✓ | 新手机号 13912345678 登录：首项 assess_first「完成首次六维测评」（D1） |
